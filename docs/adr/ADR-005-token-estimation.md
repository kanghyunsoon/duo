# ADR-005: 토큰 추정 방식

- 상태: Proposed
- 날짜: 2026-09-27
- 결정권자: Human

## 배경

Context 지표와 budget은 토큰 단위다. 실제 토큰 수는 모델마다 다르다. 절감률은 같은 추정기로 계산한 비율이므로 추정기 편향의 영향이 작지만, budget 준수(NFR-06)는 추정기 기준이다.

## 선택지

| 후보 | 장점 | 단점 |
|---|---|---|
| 문자 수 휴리스틱(예: UTF-8 bytes / 4) | 의존성 없음, 매우 빠름 | 한글, 코드에서 오차 큼 |
| 순수 JS BPE 토크나이저(o200k_base 등) | OpenAI 계열과 일치, 네이티브 없음 | 의존성 크기, 속도, Anthropic 모델과 불일치 |
| Provider API 토큰 카운트 | 정확 | 네트워크 필요(Local-first 위반) |

## 결정

`TokenEstimator` interface를 두고 기본 구현은 순수 JS BPE(o200k_base)로 한다. 라이브러리는 T10에서 크기와 속도를 비교해 고른다. 모든 지표에 `estimator` 이름을 기록한다. budget은 추정기 기준이며 문서와 출력에 "estimated"로 표시한다.

## 결과

- 파일별 토큰 수는 fingerprint 단계에서 한 번 계산해 저장하므로 반복 비용이 없다.
- 1만 파일 기준 계산 시간이 NFR-04를 위협하면 큰 파일에 한해 휴리스틱으로 대체하고 그 사실을 지표에 기록한다.
