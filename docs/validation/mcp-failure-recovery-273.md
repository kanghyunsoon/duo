# MCP server failure and recovery investigation (Jira S15P31A106-273)

This report records the failure modes, observed server/client behavior, diagnostic contracts, and recovery mechanisms of the `duo-director` MCP server (`duoctl mcp`), verified deterministically without LLM calls in [`tests/mcp/failure-recovery.e2e.test.ts`](../../tests/mcp/failure-recovery.e2e.test.ts) and [`tests/mcp/isolation.e2e.test.ts`](../../tests/mcp/isolation.e2e.test.ts).

## Scope and architectural invariants

`duoctl mcp` is a long-lived `stdio` JSON-RPC server started once per coding-agent session (Codex or Claude Code). Its failure and recovery design relies on four invariants in `packages/integration/src/mcp/server.ts`, `packages/integration/src/mcp/tools.ts`, and `packages/integration/src/operations/common.ts`:

1. **Per-call stateless storage access**: Every tool invocation loads Project Truth from `.duo-project/` and opens/closes its SQLite `GraphStore` reader (`withGraphReader`) inside `try/finally`. No SQLite snapshot or open transaction is held across calls.
2. **Fail-closed authority boundary (`requireCompleteTruth`, T40 N1)**: `loadProjectTruth` is tolerant so `duo_get_status` can describe broken Truth files under `truth.errors` and `duo_get_decision` / `duo_get_requirement` omit unreadable definition files as `status: "not-found"`, while authoritative index/context/review operations (`compileContext`, `reviewChanges`, `refreshIndexIfSafe`) refuse partial or malformed Truth with `PROJECT_TRUTH_INVALID` / `YAML_SYNTAX_ERROR`.
3. **Wire and process isolation (`T16.1`, `#172`, `#198`)**: Unexpected exceptions inside a tool handler are caught and returned as `{ isError: true }` (`MCP_INTERNAL_ERROR`) for that call only; `stdout` carries exclusively JSON-RPC frames while diagnostics and auxiliary warnings (`METRICS_WRITE_FAILED`, Work map lock timeouts) go to `stderr`. Client request cancellation (`notifications/cancelled`) aborts `ctx.mcpReq.signal`, interrupting both `withIndexWriteLock` waiting and in-flight operations.
4. **OS-backed index lock and CLI fallback**: Index refreshes use an OS file lock (`.duo-project/generated/index-writer.lock`) that the kernel releases automatically if a process crashes (`#148`). When the MCP server is unavailable, the agent bridge (`AGENTS.md` / `CLAUDE.md`) directs the agent to equivalent `duoctl` CLI commands (`duoctl status`, `duoctl context`, `duoctl review`).

## Failure and recovery matrix (`F1`–`F4`)

| ID | Fault injected | Observed MCP behavior during fault | Recovery action | Post-recovery state (`duoctl mcp` restart required?) |
|---|---|---|---|---|
| **F1a** | Corrupt Decision YAML (`.duo-project/decisions/D-001.yaml`) while server runs | `duo_get_status` succeeds (`isError: false`) and lists `YAML_SYNTAX_ERROR` in `truth.errors`. `duo_get_context` and `duo_review_changes` see the stale Truth file, attempt `refreshIndexIfSafe`, and return `status: "index-required"` with `indexRefresh: { refreshed: false, reason: "Project Truth could not be read completely..." }`. `duo_get_decision({ id: "D-001" })` omits the unreadable file (`status: "not-found"`). | Restore valid YAML in `.duo-project/decisions/D-001.yaml`. | **No restart required.** Same MCP server PID immediately returns `truth.errors: []`, `duo_get_decision` `status: "found"`, and `status: "ready"` on the next call. |
| **F1b** | Corrupt root `.duo-project/project.yaml` while server runs | `loadProjectTruth` fails (`value === undefined`); `duo_get_status`, `duo_get_context`, and `duo_review_changes` all return `isError: true` (`YAML_SYNTAX_ERROR` / `PROJECT_FILE_INVALID`). Server stays alive. | Restore valid `.duo-project/project.yaml`. | **No restart required.** Same MCP server PID immediately serves `status: "ready"` on the next call. |
| **F2a** | Corrupt `.duo-project/generated/graph.db` with non-SQLite bytes | `duo_trace` and graph-backed calls fail closed (`isError: true` or `index-required`); `duo_get_status` reports non-current index or failure without crashing the server. | Remove corrupt DB files and run `duoctl index --full`. | **No restart required.** Because `withGraphReader` opens `graph.db` per call, the same MCP server PID immediately reads the rebuilt index (`index: "current"`). |
| **F2b** | Obstruct `.duo-project/runtime/metrics.jsonl` (replace file with a directory) and hold `work-tasks.lock` | Metered tools (`duo_get_context`, `duo_review_changes`) still return `isError: false` and `status: "ready"`. `stderr` logs `duo-director: METRICS_WRITE_FAILED: ...` and `duo work activity task failed after ... ms`. `stdout` stays pure JSON-RPC. | Remove the obstruction / release `work-tasks.lock`. | **No restart required.** Subsequent metered calls recreate `metrics.jsonl` and resume activity logging. |
| **F3a** | Cancel `duo_get_context` (`AbortController.abort()` after 250 ms wait) while waiting on a held `withIndexWriteLock` (`#172`, `#198`) | Server-side `withIndexWriteLock` aborts within one 20 ms lock-poll interval and writes the `status: "index-required"` runtime metric (`durationMs < 5,000`) while the external lock is still held, instead of waiting 30 s. When the external lock is released, no lingering server request steals the lock (`index.status` stays `"stale"`), and `duo_get_status` stays responsive throughout. | Release the external index write lock and retry `duo_get_context`. | **No restart required.** Next `duo_get_context` on the same MCP connection acquires the lock immediately (`< 5,000 ms`), refreshes the stale index once (`indexRefresh: { refreshed: true }`), and returns `status: "ready"`. |
| **F3b** | Uncaught tool exception (`MCP_INTERNAL_ERROR`) or invalid schema arguments (`T16.1`) | Call returns `isError: true` (`MCP_INTERNAL_ERROR` on `stderr: INTERNAL <tool>: <msg>`, or Zod validation error). `stdout` framing is preserved. | Send a valid subsequent tool call on the same connection. | **No restart required.** Immediate next `duo_get_status` / `duo_get_context` call on the same connection succeeds. |
| **F4a** | Graceful client disconnect (`client.close()` / `stdin` EOF / `SIGTERM`) | `serveDuoMcp` closes the stdio transport, invokes `disconnectWorkSession(root, duoSessionId, ...)`, marks active session tasks as `status: "disconnected"` in `.duo-project/runtime/work-tasks.json`, and exits `0`. | Host spawns a new `duoctl mcp` session when needed. | Clean shutdown (`exit 0`); Work map reflects `disconnected` status. |
| **F4b** | Abrupt MCP server crash (`process.kill(pid, "SIGKILL")`) + source edits while server is down | In-flight/subsequent calls on the dead client transport reject. OS kernel releases any held file lock handles. | 1. Agent uses CLI fallback (`duoctl status`, `duoctl context --refresh`, `duoctl review`).<br>2. Host spawns a fresh `duoctl mcp` server. | CLI fallback completes with `0` errors. Reconnected `duoctl mcp` auto-refreshes the stale index (`indexRefresh: { refreshed: true }`) and returns `structuredContent` deep-equal to `duoctl review --json`. |
