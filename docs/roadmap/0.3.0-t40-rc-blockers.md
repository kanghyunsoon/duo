# T40 — 0.3.0 RC Blocker Closure

branch `next`. T39의 P0(N1)과 P1(N2~N5)만 닫는다. 새 기능 없음. publish·tag·release 없음.

## 1. N1 원인

`loadProjectTruth()`는 설계상 관대하다. 읽지 못한 파일을 빼고 나머지 Project Truth를 value로, 문제는 diagnostics로 함께 돌려준다(docs/03). 문제는 상위 경계였다. review(`reviewChanges`), context(`compileContext`), Adoption Baseline 캡처, CLI `requireProject`, integration `project()`, doctor, DecisionService가 모두 `value !== undefined`만 확인하고 diagnostics를 버렸다. 그래서 확정된 `enforcement: block` Decision에 모르는 field(`SCHEMA_UNKNOWN_PROPERTY`), 잘못된 YAML, 잘못된 타입이 있으면 그 Decision이 Truth에서 조용히 빠졌다. status는 개수만 줄고, doctor는 `truth.project: valid`, review는 그 Decision이 금지한 변경을 PASS로 냈다. review JSON에도 흔적이 없었다. 0.2.1도 같다.

## 2. fail-closed 경계

선택: loader 계약은 그대로 두고, 권위 있는 판정을 하는 작업에 `requireCompleteTruth()`(core `loader/authority.ts`) 경계를 둔다.

- 막는 대상: error severity인 loader 진단 전부. 예외는 내용을 빼지 않는 참조 무결성 코드 `BROKEN_REFERENCE`, `REFERENCE_TYPE_MISMATCH` 둘뿐이다. 차단 목록이 아니라 예외 목록이라 나중에 생기는 loader error도 자동으로 막힌다.
- 적용 작업: review, context, Adoption Baseline 캡처, Decision confirm·reject·repair·preview.
- 적용하지 않는 작업: index(상태 표시가 계속 되도록), status, doctor(오류를 보여 줌), trace·impact·search·get_decision(판정 아님), propose(proposal은 권한이 없고 agent가 고치는 제안을 해야 할 수 있음. 그 confirm은 거부됨).

A(권위에 중요한 진단만 분류)와 B(모든 error를 fatal) 중 A의 변형을 골랐다. 기존 audit 결과, 참조 오류(`BROKEN_REFERENCE`, `REFERENCE_TYPE_MISMATCH`)는 정의를 지우지 않고 trace·review rule(`supersede-integrity`)이 이미 다룬다. 이것까지 fatal로 하면 Decision이 없는 Requirement를 가리키는 오타 하나로 review 전체가 멈춘다. 반대로 내용을 지우는 오류(파일 읽기, YAML, schema, ID, Markdown metadata, `DUPLICATE_ID`)와 권한을 모호하게 하는 오류(`DECISION_SUPERSEDES_SELF`, `DECISION_SUPERSEDE_CYCLE`)는 판정을 바꿀 수 있으므로 막는다. 기존 테스트 중 일부만 읽힌 Truth로 review·context를 기대한 것은 없었다. DecisionService의 기존 supersede 오류 테스트는 propose를 허용하도록 범위를 좁혀 그대로 통과했다.

## 5. 0.2.x backport 평가

v0.2.1에서 분리한 임시 worktree에 N1 commit(`0c59d47`)을 cherry-pick했다(commit·branch 없이, 확인 후 삭제).

- 충돌 3개, 모두 위치 충돌이다. 0.2.1에 없는 Informed Confirm 코드 옆에 N1 줄이 있어서 생겼다: `diagnostics.ts`의 persistence 줄, `messages.ts`의 preview 메시지 옆, `decision.ts`의 import 줄. 0.2.1 쪽을 유지하고 N1 줄만 남기면 끝나며 의미 판단이 필요 없다.
- 결과: typecheck·lint·build 통과, N1 테스트와 DecisionService·UI·doctor·existing-project 테스트 53개 통과.
- 실제 효과: T39의 0.3 저장소(`imported_paths`를 쓴 D-003)에 위반 import를 넣으면 공개 0.2.1은 `WARN 0 claims`(종료 코드 0)로 놓치고, backport 빌드는 review 거부(종료 코드 1, D-003 경로와 `forbids.imported_paths` 명시), status `Truth errors: 1`, doctor `action required`.
- machine contract 영향: 새 진단 코드 1개, status `truth.errors` 추가, 일부만 읽힌 Truth에서 review·context가 결과 대신 종료 코드 1. 정상 Truth의 동작·형식 변경 없음.
- 안전성: 변경이 경계 함수 하나와 그 호출부에 한정되고 정상 경로를 바꾸지 않으므로 correctness-only patch로 적합하다.

제안 0.2.2 범위: N1 fail-closed 수정과 그 테스트, release note. H-71, `imported_paths`, T34~T38 기능, 0.3 UX는 넣지 않는다. 0.2.2를 내려면 별도 Human Decision(초안 아래)이 필요하다. External Validation은 계속 정확히 0.2.1이며, 참가자 version을 자동으로 바꾸지 않는다. validation 중 N1 조건(읽지 못한 Truth로 PASS)이 실제 생기면 critical correctness incident로 기록하고 그 evidence를 정상 PASS로 해석하지 않는다.

> H-75 초안(기록하지 않음): 0.2.2 correctness patch. (1) N1 fail-closed 수정(`requireCompleteTruth` 경계, `PROJECT_TRUTH_INVALID`, status `truth.errors`, doctor invalid)을 v0.2.1 위에 backport하고 테스트를 함께 넣는다. 다른 변경은 넣지 않는다. (2) dist-tag `latest`로 publish할지는 External Validation 01과의 관계(H-67 (11): 참가자 version 고정, critical 문제 시 PAUSE)를 보고 정한다. 참가자 version을 자동으로 바꾸지 않는다. (3) 0.3 저장소의 downgrade floor를 0.2.2로 한다.

## 6. schema_version 대안

현재 `SUPPORTED_SCHEMA_VERSIONS = [1]`이고, 0.2.1은 지원하지 않는 `schema_version`을 보면 project 전체를 거부한다(`UNSUPPORTED_SCHEMA_VERSION`, value 없음). 따라서 0.3 전용 field를 쓸 때 project.yaml을 `schema_version: 2`로 올리면 0.2.1도 조용히 넘어가지 않고 실패한다. 하위 버전을 막는 데는 더 정석적인 방법이다. 그러나 다음 이유로 이번에 구현하지 않는다.

- 누가 언제 올리는가: Decision confirm이 project.yaml을 자동으로 바꾸면 Human Truth를 DUO가 고치는 것이다(ADR-006, 쓰기 경계). 사람이 직접 올리게 하면 `imported_paths`를 쓰기 전에 별도 수작업 단계가 생긴다.
- 0.3 init이 처음부터 2를 쓰면 0.3 전용 field가 없는 저장소도 0.2.x로 열 수 없게 된다(과도한 차단).
- migration 규칙(1→2의 의미, 2에서 무엇이 허용되는지)과 그 테스트가 새로 필요하다.

N1 fail-closed와 0.2.2 floor가 더 작고, 모든 unknown field(오타 포함)를 같은 방식으로 다룬다. schema_version 2는 실제로 의미가 다른 Truth 형식이 생길 때 다시 검토한다.

## 7. Downgrade floor

- 0.2.1 이하: 지원하지 않는다. `imported_paths`를 쓴 Decision을 조용히 빼고 위반을 놓친다(T39 실측).
- floor: N1을 backport한 0.2.x(제안 0.2.2, 미출시). 그런 version은 review를 거부하고 파일을 보인다(backport 빌드 실측).
- release note([notes-0.3.0-rc.1](../release/notes-0.3.0-rc.1.md#downgrade)): 0.3 전용 field가 있는 저장소를 0.2.1 이하로 열지 말 것. 0.2.2가 나오기 전에는 지원되는 downgrade가 없으며, 되돌리려면 그 Decision을 field 없는 Decision으로 먼저 supersede한다.
