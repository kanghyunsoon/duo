# T71 — README external-source-drift provenance audit (Issue #7)

날짜: 2026-10-12. 대상: 공개 [#7](https://github.com/kanghyunsoon/duo/issues/7) "Editing README after setup makes every review WARN". 기준: `next` `9d5ae7a`, 재현은 registry `@duo-director/cli@0.3.1`. 감사만 했고 제품 동작은 바꾸지 않았다(H-84 (4)).

## 1. 결론

**분류: POLICY-CHANGE** (RECOVERY-ONLY 조건도 함께 성립).

- 현재 동작은 계약대로다. ADR-014·H-16은 External Source provenance를 `{path, hash, section?}`로 정하고, section이 없으면 파일 전체 hash, hash가 바뀌면 R-DRIFT가 PARTIAL을 낸다고 정했다. init은 README 첫 문단을 vision으로 채택할 때 section 없이 파일 전체 hash를 기록한다. 그래서 README의 어느 부분을 고쳐도 drift이고 WARN이다. file 단위 구현이 계약보다 과한 bug가 아니다(PATCH-SAFE 아님).
- #7의 기대 동작(채택한 문장과 무관한 README 편집은 attention WARN이 아님)은 provenance 단위나 drift verdict 정책을 바꾸는 일이다. 0.4의 WARN attention 정책([#5](https://github.com/kanghyunsoon/duo/issues/5), Epic [#2](https://github.com/kanghyunsoon/duo/issues/2))과 함께 다룬다.
- 사람이 바뀐 source를 다시 받아들이는 정식 방법(명령, 문서, 출력 안내)은 없다. 수동으로 vision.md의 hash를 새 값으로 바꾸면 PASS로 돌아오지만 어디에도 안내되지 않는다. 0.3.2에서 할 수 있는 것은 이 안내뿐이고, 넣을지는 H-85 초안으로 사람이 정한다.
- 새 C-ID는 만들지 않았다. 계약을 벗어난 product defect가 확인되지 않았다(다음 미사용 번호 C274는 소비하지 않음).

## 2. 재현

registry 0.3.1, 새 Git 저장소, `core.autocrlf false`. README:

```markdown
# demo

A tiny demo project for testing DUO.

## Usage

Run the demo with node.

## License

MIT
```

`duoctl init`에서 README 제안("A tiny demo project for testing DUO.")을 받아들이고 commit, `duoctl index` 뒤 README만 바꿔 `duoctl review`:

| 경우 | 변경 | verdict | external-source-drift |
|---|---|---|---|
| A | 채택한 문장 자체("… for testing DUO and friends.") | WARN | PARTIAL `external-source-changed` |
| B | 다른 문단("Run the demo with Node.js 24 or newer.") | WARN | PARTIAL `external-source-changed` |
| C1 | typo("node" → "Node") | WARN | PARTIAL `external-source-changed` |
| C2 | 끝 공백 두 칸 추가 | WARN | PARTIAL `external-source-changed` |
| C3 | 줄바꿈만 LF → CRLF | PASS | ALIGNED `external-source-unchanged` |
| - | 변경 없음 | PASS | claim 없음 |

A·B·C1·C2는 구별되지 않는다. C3만 canonical text(CRLF → LF)라 drift가 아니다. 다른 claim은 없었다. claim 문구(A): expected "README.md has hash sha256:ba23db5c… as confirmed for .duo-project/intent/vision.md", observed "README.md now has hash sha256:0ae66286… (the confirmed Truth is not changed; a human decides)". T69의 실제 저장소(ky, click)에서 정상 작업 review의 WARN 3/3이 이 claim 하나였다.

수동 복구 확인: B 상태에서 vision.md의 `hash`를 observed의 새 값으로 바꾸고 다시 review하면 PASS(drift ALIGNED `external-source-unchanged`).

## 3. Source 표현과 hash

| 질문 | 답 | 위치 |
|---|---|---|
| init이 채택하는 text | README(후보 문서 순위상 readme 종류, Markdown)의 첫 문단(최대 500자). 없으면 package.json `description` | director `init/documents.ts` `firstParagraph`, `discoverDocuments` |
| 저장하는 provenance | vision.md frontmatter `source: [{ path, hash }]`. section 없음, 채택 문장 자체의 hash나 위치 없음 | `init/documents.ts`(`goal.evidence`), `init/apply.ts`(사람이 제안을 받아들일 때만 `goal.source`), `init/render.ts` |
| hash 대상 | 파일 전체의 canonical text(BOM 하나 제거, CRLF → LF) sha256 | core `provenance.ts` `externalSourceSlice`(section이 없으면 전체) |
| 위치 저장 | 없음(파일 경로만) | 같은 곳 |
| 변경 계산 | review의 reviewed side에서 문서를 읽고 같은 방식으로 hash해 기록 값과 비교 | core `compareSourceHash`, director `review/drift.ts` `externalSourceDrift` |
| 검사 대상 | confirmed vision과 confirmed·active Truth 항목 중 Review context에 있거나, Truth 파일이 바뀌었거나, source 문서가 diff에 있는 것 | `review/drift.ts` `relevant` |
| verdict | hash 불일치 → PARTIAL(drift, non-blocking) → WARN. 같으면(문서가 diff에 있을 때만) ALIGNED | ADR-007 R-DRIFT, `external-source-drift` 행 |

section은 계약에 있지만 init이 쓰지 않는다. 써도 #7에는 큰 도움이 되지 않는다. README 첫 문단은 보통 H1 제목 아래에 있고, H1 section은 다음 H1 또는 파일 끝까지라 대부분 README 전체다(위 재현 README도 그렇다).

## 4. 현재 계약

- [ADR-014](../adr/ADR-014-traceability-ids.md#provenance) Provenance: "`hash`는 `section`(Heading)이 있으면 그 섹션 텍스트, 없으면 파일 전체의 sha256이다. hash가 바뀌면 R-DRIFT가 결정적으로 PARTIAL Claim을 내고, 충돌 여부는 의미 판정(LLM이 없으면 UNKNOWN)에 맡긴다. 이 이상의 provenance 시스템은 만들지 않는다."
- [ADR-014](../adr/ADR-014-traceability-ids.md#project-truth와-external-source): 외부 문서가 바뀌어도 `.duo-project`를 자동으로 바꾸지 않고 drift로 보고한다. 바꿀지는 사람이 정한다.
- H-16([conflicts.md](../conflicts.md)): provenance는 `{path, hash}` 수준이다.
- [ADR-007](../adr/ADR-007-verdict-model.md) R-DRIFT·`external-source-drift`: hash가 다르면 PARTIAL(non-blocking), 같으면 ALIGNED.
- [07-cli-interface.md](../07-cli-interface.md): init의 Goal 질문에서 README 제안을 "받아들이면 README provenance".

채택 문장(excerpt) 단위 provenance나 "source 변경은 정보, 채택 내용 변경만 WARN"이라는 의미는 어느 결정에도 없다. 지시문의 Option A(외부 source 파일 전체가 증거라 어떤 변경도 drift)가 현재 계약이다. section을 쓰면 section 단위가 된다. Option B·C는 새 계약이다.

## 5. 복구 경로

- 명령: 없다. `duoctl init`은 이미 초기화된 저장소에서 vision을 다시 묻지 않는다. vision을 다시 확정하거나 source hash를 갱신하는 명령이 없다.
- 문서: README, 07-cli-interface, 06-mcp-interface 어디에도 "README가 바뀐 뒤 어떻게 받아들이는가"가 없다.
- 출력: observed가 새 hash와 "a human decides"를 보이지만, 무엇을 하면 되는지는 말하지 않는다.
- 실제로 되는 방법: 사람이 README 변경을 확인한 뒤 vision.md의 `hash`를 새 값으로 바꾸거나(위 재현에서 PASS), vision을 새로 쓰고 `source`를 지운다. vision.md는 사람 소유 Truth이므로 계약상 허용된다.
- 위험: 안내가 없으면 Agent가 WARN을 없애려고 vision.md hash를 바꿀 수 있다. bridge는 "BLOCK을 우회하려고 Project Truth를 고치지 말라"고만 말한다. 안내를 넣는다면 사람이 하는 일로 적어야 한다.

## 6. 선택지

| 선택지 | 내용 | 계약 변화 | 시점 |
|---|---|---|---|
| 1. 그대로 | 동작·문구 변경 없음 | 없음 | - |
| 2. 복구 안내 | `external-source-changed` claim을 사람에게 보일 때(CLI review 출력, MCP text) 받아들이는 방법 한 줄. verdict, claim field, JSON `/1`, Truth 형식은 그대로 | 없음(출력 문구) | 0.3.2 가능(H-85 필요) |
| 3. 채택 문단 단위 provenance | init이 채택한 문단의 hash(와 위치)를 기록하고 그 문단이 바뀔 때만 drift | provenance 형식·ADR-014 변경 | 0.4 |
| 4. source 변경은 정보로 | file hash 불일치는 informational, 채택 내용이 달라졌을 때만 attention WARN | R-DRIFT verdict 정책 변경 | 0.4([#5](https://github.com/kanghyunsoon/duo/issues/5)와 함께) |

3과 4는 기존 저장소의 vision.md(파일 hash만 있음)를 어떻게 읽을지도 정해야 한다.

## 7. H-85 초안(미승인)

사람이 정할 내용이다. 이 문서는 초안만 적고 `conflicts.md`에 기록하지 않았다.

> H-85 (초안) Issue #7 README external-source-drift. (1) ADR-014·H-16의 file·section 단위 provenance와 R-DRIFT의 PARTIAL(WARN) 의미는 0.3.2에서 바꾸지 않는다. (2) 채택 문장과 무관한 README 편집이 attention WARN을 내지 않게 하는 일(선택지 3 또는 4)은 provenance·verdict 정책 변경이므로 0.4에서 #5 WARN attention 정책과 함께 설계한다. (3) 0.3.2에는 [선택지 2: 사람용 복구 안내 한 줄만 / 아무것도 넣지 않음] 중 하나를 넣는다. 선택지 2는 verdict, claim field, JSON `/1`, Truth 형식, migration을 바꾸지 않으며, 안내는 사람이 README 변경을 확인한 뒤 vision.md source를 갱신하는 일로 적는다(Agent가 대신하지 않음). (4) External Validation 01은 정확히 0.2.1이다.

maintainer 권고: (3)은 선택지 2. 출력 문구만 바뀌고, T69에서 사람이 매번 읽던 WARN에 다음 행동이 생긴다.
